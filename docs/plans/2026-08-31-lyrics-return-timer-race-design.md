# 歌词二次拖动回位计时器竞态设计

## 问题

用户第一次拖动歌词并释放后，组件会启动 3 秒自动回位计时器。若用户在倒计时结束前再次按下歌词区域，旧计时器当前不会立刻取消；它要等到第二次手势真正产生滚动更新后才会被取消。因此，在按下、越过拖动识别阈值或首个滚动更新到达之前，旧计时器可能到期并把歌词强制滚回当前播放行。

## 设计

把“新交互已经接管歌词面板”定义为歌词区域收到新的指针按下或触控板平移缩放手势开始，而不是等到滚动位移产生。此时立即取消并清空上一轮的回位计时器。

新手势结束后的行为保持不变：

- 没有产生滚动时，从手指释放时重新启动完整倒计时；
- 产生滚动或惯性滚动时，从滚动结束时重新启动完整倒计时；
- 桌面鼠标滚轮继续按每次滚轮信号刷新倒计时；
- 播放跟随、点击歌词跳转、中心播放箭头与逐字歌词高亮逻辑不变。

## 方案比较

1. 在指针按下和触控板手势开始时取消计时器（采用）。这是最早能确认用户重新接管面板的时机，且现有释放/滚动结束逻辑已经负责重启计时器。
2. 在 `ScrollStartNotification` 时取消。实现简单，但拖动识别前仍有竞态窗口，不能满足“按下后立即取消”。
3. 为每个计时器增加代际令牌。可以防御陈旧回调，但仍需要在新手势开始时使旧代际失效，当前单计时器模型没有必要引入额外状态。

## 验证

新增 Widget 回归测试：第一次拖动释放，在旧倒计时即将到期时开始第二次真实指针手势并保持按下，跨过旧计时器及回位动画时长后，中心播放箭头仍存在；释放第二次手势后，必须再等待完整倒计时才回到当前播放歌词。
